## rules
- Define clear module boundaries. Keep dependencies between modules one-way.
- Write tests together with the code. New code needs tests.
- Document decisions that are not obvious in the repo docs.
- Prefer explicit types and clear names over short code.
- Keep the build, lint and test commands fast and passing.

## ask-first
- Add a new top-level module, service or major dependency.
