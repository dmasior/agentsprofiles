## rules
- Write for the task of the reader. Start with what the reader must do.
- Use short sentences, active voice and consistent terms.
- Test every command and code sample before you publish it.
- Update docs in the same change as the code they describe.
- Follow the existing doc structure and style guide of the project.

## never
- Do not document features that do not exist yet.
